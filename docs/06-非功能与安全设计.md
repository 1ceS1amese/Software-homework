## 1. 容量估算与设计上限

| 维度 | 设计上限 | 超过后的表现 |
|---|---|---|
| 单学期教学班 | 5 000 | 需分页强制，禁止导出全量 |
| 单学期选课记录 | 500 000 | 查询走索引；统计改走汇总表（P2） |
| 并发用户 | 200 | 超出后进入队列等待，表现为 P95 上升 |
| 单表行数 | 500 万 | 需评估归档/分表（`docs/11` RISK-06） |

**依据**：单班 40 人 × 5000 班 = 20 万；加退选历史与演示数据，取 50 万为上限。

## 2. 性能预算

### 2.1 响应时间目标

| 接口类别 | P95 | P99 | 备注 |
|---|---|---|---|
| 登录 | < 400ms | < 800ms | 含 BCrypt 开销 |
| 教学班列表 | < 500ms | < 900ms | 强制分页，`size ≤ 100` |
| 选课提交 | < 800ms | < 1500ms | 含行锁等待与重试 |
| 退课 | < 600ms | < 1200ms | |
| 我的课表 | < 400ms | < 800ms | |
| 成绩批量保存（50 人） | < 800ms | < 1500ms | 单事务批量 upsert |
| 统计类 | < 2000ms | < 4000ms | 允许更慢，但必须有超时与友好提示 |

**测量口径**：不含浏览器渲染时间；后端以 `traceId` 为单位打点，`/actuator/metrics` 可观测。

### 2.2 关键手段

| 手段 | 说明 |
|---|---|
| 索引 | 见 `02` §9；上线前对每条查询执行 `EXPLAIN`，禁止全表扫描 |
| 分页 | 所有列表强制分页；深分页（`page > 1000`）限制为拒绝而非慢查询 |
| 批量 | 成绩保存、选退课批量处理用单条批量语句，禁止循环单条 |
| 连接池 | HikariCP 默认 20，选课高峰调至 50；`connectionTimeout=3000ms` 防止请求堆积 |
| 慢查询 | MySQL `slow_query_log` 开，日志目录挂载并每日巡检 |
| 本地缓存 | **仅**统计类配置（权重、学分上下限）做 60s 本地缓存；选课相关数据**禁止缓存** |
| 前端 | 列表请求防抖 300ms；同一组件销毁时取消在途请求（`AbortController`） |

### 2.3 明确不做的性能优化

| 不做 | 理由 |
|---|---|
| Redis 缓存选课数据 | 强一致场景下缓存必然引入不一致风险（`01` ADR-05） |
| 读写分离 | 本项目写压力大（选课），读分离收益低、复杂度高 |
| 分布式锁 | 数据库行锁已足够（`02` §6） |

## 3. 安全设计

### 3.1 认证与会话

| 项 | 设计 |
|---|---|
| 密码存储 | BCrypt(strength=10)，**永不可逆**，无找回功能，只能重置 |
| Token | JWT 存 `localStorage`（非 Cookie，故无 CSRF 面）；有效期默认 2h |
| 传输 | 生产强制 HTTPS（`06` §7 Nginx 配置） |
| 强制改密 | 管理员重置后 `mustChangePwd=1`，前端强制跳转改密页，未改密不得访问其他页面 |
| 登录枚举防护 | 用户不存在与密码错误返回**同一 code 与文案** |
| 暴力破解 | 5 次失败锁 15 分钟（可配），记录到 `sys_login_log` |
| 账号停用 | `status=DISABLED` 即刻生效（每次请求从 JWT 解析角色，但停用需查库校验或短 TTL 缓存——实现时以 JWT 版本号方案，见 `docs/11` AS-07） |

### 3.2 授权

| 项 | 设计 |
|---|---|
| 认证 | Spring Security 过滤器链 + JWT |
| 授权 | URL 级（角色）+ 方法级（资源归属校验，BR-14） |
| 越权测试 | 每个受保护接口至少一条"其他角色调用 → 403"用例（`07` §5） |
| 水平越权 | 学生 A 访问学生 B 的选课记录 → 403；教师 A 访问教师 B 的教学班成绩 → 403 |

### 3.3 输入与输出安全

| 威胁 | 措施 |
|---|---|
| SQL 注入 | MyBatis `#{}` 预编译；排序字段白名单映射 |
| XSS | Vue 默认文本插值转义；**禁止 `v-html`**，确需时先经 DOMPurify |
| CSRF | 无状态 + 不使用 Cookie 存 Token；关闭 CSRF filter |
| 越权访问 | 见 §3.2 |
| 批量枚举 | 列表接口强制分页 + `size ≤ 100`；导出接口需管理员权限且有审计 |
| 敏感数据 | 手机号/邮箱序列化层脱敏（`03` §5.3） |
| 错误信息 | 响应不含堆栈/SQL/表名；仅返回 `traceId` 供排查 |
| 文件上传 | 仅 `.csv`，≤2MB，MIME+扩展名双校验，读取时检查是否含 `=cmd|` 公式前缀（防 CSV 注入导出侧） |

### 3.4 限流与防滥用

| 措施 | 阈值 | 说明 |
|---|---|---|
| 登录限流 | 同 IP 10 次/分钟 | 超出 `429` |
| 选课限流 | 同账号 30 次/分钟 | 防脚本刷选 |
| 写操作限流 | 同账号 60 次/分钟 | 通用兜底 |
| 实现 | 应用内令牌桶（单机，无 Redis）；多实例部署时改为网关层限流（`docs/08` §5） | |

> 限流实现可作为 P1；**登录限流必须在 P0**（配合锁定策略）。

### 3.5 依赖安全

| 项 | 措施 |
|---|---|
| 漏洞扫描 | CI 中执行 `mvn org.owasp:dependency-check-maven:check`（失败即阻断） |
| 前端审计 | CI 中执行 `pnpm audit --audit-level=high` |
| 依赖锁定 | 提交 `pom.xml` 与 `pnpm-lock.yaml`，CI 使用锁文件安装 |
| 补丁 | 依赖版本以 registry 实际解析为准，定期升安全补丁（`docs/11` AS-02） |

## 4. 日志与审计

### 4.1 三类日志的分工

| 类型 | 内容 | 保留期 | 目的地 |
|---|---|---|---|
| 应用日志 | 请求日志、异常、业务关键点 | 30 天 | `logs/app.log`（滚动） |
| 审计日志 | 业务操作前后值（`sys_audit_log`） | 永久（归档后长期） | 数据库 |
| 登录日志 | 登录成败（`sys_login_log`） | 180 天 | 数据库 |

### 4.2 日志格式

- 结构化输出，每行含：`时间 | level | traceId | userId | 模块 | 事件 | 耗时`。
- 异常日志含完整堆栈；`WARN` 及以上脱敏（`03` §5.3 清单）。
- **禁止打印**：请求体全文、响应体全文、密码、Token、身份证号。

### 4.3 审计覆盖清单（BR-16）

| 动作码 | 触发 |
|---|---|
| `LOGIN_SUCCESS` / `LOGIN_FAIL` / `LOGOUT` | A-01 / A-02 |
| `USER_CREATE` / `USER_UPDATE` / `USER_DELETE` / `USER_RESET_PWD` / `USER_STATUS_CHANGE` | U-02/04/05/06/07 |
| `DEPT_*` `MAJOR_*` `TERM_*` `COURSE_*` `CONFIG_UPDATE` | B-02~B-22 |
| `CLASS_CREATE` `CLASS_UPDATE` `CLASS_DELETE` `CLASS_STATUS_CHANGE` | C-02~C-06 |
| `ENROLL_CREATE` `ENROLL_WITHDRAW` | E-01 / E-02 |
| `GRADE_SAVE` `GRADE_PUBLISH` `GRADE_UNLOCK` `GRADE_IMPORT` | G-02/04/05/06 |

### 4.4 审计可靠性

- 异步写入；若审计队列满 → 丢弃 + 计数指标 `csms.audit.dropped` 并打 WARN。
- **已知权衡**：极端崩溃可能丢最后若干条审计（`docs/11` RISK-05）。若要求零丢失需改同步写，代价是主链路延迟 +3~5ms 且审计失败会拖垮业务。**当前选择吞吐与可用性**。

## 5. 可观测性

### 5.1 健康与指标

| 端点 | 用途 |
|---|---|
| `/actuator/health` | 存活与就绪；包含数据库连通性 |
| `/actuator/metrics` | 关键指标暴露 |
| `/actuator/info` | 构建信息（版本、提交号、构建时间） |

**关键业务指标**（自定义 Micrometer 计数器/仪表）：

| 指标 | 类型 | 用途 |
|---|---|---|
| `csms.enroll.attempt` | Counter(按 result 标签) | 选课成功率与失败原因分布 |
| `csms.enroll.reject.reason` | Counter(按错误码标签) | 观察最常见的被拒原因 |
| `csms.enroll.capacity_mismatch` | Gauge | 名额对账结果（正常为 0） |
| `csms.audit.dropped` | Counter | 审计丢弃量 |
| `csms.sql.rollback` | Counter | 事务回滚次数 |
| `csms.deadlock.retry` | Counter | 死锁重试次数 |

### 5.2 告警建议（部署后接监控系统，本期只定义指标）

| 条件 | 级别 | 动作 |
|---|---|---|
| `csms.enroll.capacity_mismatch > 0` | 高 | 立即人工核查（数据不一致） |
| 5xx 比例 > 1% 持续 5 分钟 | 高 | 值班介入 |
| P95 超过 `06` §2.1 预算 2 倍持续 10 分钟 | 中 | 排查慢查询 |
| `csms.audit.dropped > 0` | 中 | 审计队列配置问题 |

## 6. 备份与恢复

| 项 | 策略 |
|---|---|
| 备份类型 | 开发/演示环境：每日全量 `mysqldump`；保留 7 份 |
| 备份验证 | **每季度至少一次恢复演练**（恢复到临时库并跑 §2 一致性对账 SQL） |
| 恢复目标 RPO | ≤ 24h（演示环境） |
| 恢复目标 RTO | ≤ 2h |
| 文件备份 | 上传文件（若启用）随库备份 |

> **明确**：本项目当前**无生产环境**，备份策略是面向部署后的建议，不代表已建立备份链路（`docs/10` 未验证项）。

## 7. 部署态安全

| 项 | 配置 |
|---|---|
| HTTPS | Nginx 配置 `ssl_certificate`；80 全量跳转 301 到 443 |
| 安全响应头 | `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: strict-origin-when-cross-origin`、CSP（按前端实际资源域调整） |
| CORS | 生产**不开启**（同源） |
| 限流 | Nginx `limit_req` + 应用内限流双层 |
| 敏感配置 | `JWT_SECRET`、数据库密码经环境变量注入，**不入仓库、不进日志** |
| 默认账号 | 部署后**必须**修改演示账号密码，或初始化脚本加 `mustChangePwd=1` |
| 端口暴露 | 应用仅监听内网/本机；数据库端口不对外 |

| 项 | 要求 |
|---|---|
| 浏览器 | Chrome / Edge 最近两个大版本；Firefox 最新版基本可用 |
