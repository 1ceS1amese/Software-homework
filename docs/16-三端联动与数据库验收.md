# 16 三端联动与数据库验收

## 1. 范围与判定

本次必须验证两条要求：① 前端新增、修改、删除经后端业务处理并持久化；② 一个角色操作后，另一个独立登录角色应当自动看到业务变化和提示。

“多端”按 AS-18 指管理员、教师、学生三个 Web 端及独立会话；手机、平板、桌面使用响应式界面。在线页面每 5 秒同步，恢复前台立即补查；离开页面停止查询。禁止将本实现表述为原生 App、离线消息中心、短信或历史通知队列。

| 功能点 | 必须观察的行为 | 自动化用例 |
|---|---|---|
| AC-01 课程管理 | 管理员页面增改删落库，刷新后仍正确；重复/非法字段/引用删除/越权必须拒绝，成功操作留审计 | `course-admin.spec.ts` |
| AC-02 选退课 | 只能学生自主选课；教师只能看自己的名单；重复与退课幂等、重选、20 人抢 1 席必须无超卖；代选来源/账户状态正确 | `enrollment.spec.ts` |
| AC-03 选课互动 | 学生页面选退课，教师独立会话不手工刷新即可更新名单、人数与通知 | `roster-sync.spec.ts` |
| AC-04 成绩处理 | 教师页面保存、修改、发布；服务端计算总评；跨班记录、非法分数整批拒绝；发布锁、解锁原因、审计故障事务回滚 | `grade-security.spec.ts` |
| AC-05 成绩互动 | 学生独立会话自动显示发布/撤回与提示；学业概览同步；已完成课程保留在课表、已选学分和学分上限内 | `grade-sync.spec.ts` |
| AC-06 兼容性 | 三浏览器引擎、390/768/1440 像素宽度、导航/表单/课表/旧调用、鉴权/CORS、追踪号与本地图标；组合操作后数据库无异常 | `compatibility.spec.ts`、`menu-accessibility.spec.ts`、`response-contract.spec.ts`、`zz-consistency.spec.ts` |

用例位于 `frontend/tests/acceptance/`，必须访问真实前端、后端和 MySQL；此套件禁止模拟业务接口。原有 `tests/e2e` 的模拟接口测试仍应保留，用于界面失败分支与竞态回归。测试结论、基线失败与二次校验记录见 [验收证据](evidence/acceptance-20261016.md)。

## 2. 自动验收

在项目根目录执行。先按 docs/12 准备 Java 17、MySQL 8、Node、pnpm、Python 原生工具及前端依赖；测试期间禁止启动 Docker 或 Testcontainers。

```bash
source scripts/env.sh
(cd frontend && pnpm install --frozen-lockfile)
(cd frontend && pnpm exec playwright install chromium firefox webkit)

# 后端 JUnit、前端 Vitest、模拟接口 E2E
./scripts/test.sh

# 新建隔离实例，打包后端，执行三个引擎的真实写入与兼容性测试
./scripts/test.sh acceptance

# 单独复验一个功能点；-- 后面的参数传给 Playwright
./scripts/test.sh acceptance -- course-admin.spec.ts --project=chromium
./scripts/test.sh acceptance -- grade-security.spec.ts --project=firefox

# 在另一个全新实例进行第二轮完整校验
./scripts/test.sh acceptance
```

Ubuntu/Debian 等 Playwright 支持的系统应按 [官方浏览器依赖指南](https://playwright.dev/docs/browsers#system-dependencies) 准备运行库，可在 `frontend` 目录执行 `pnpm exec playwright install-deps chromium firefox webkit`。Arch 不在官方支持清单内，项目引导器只保证原有 Chromium 运行库；Firefox/WebKit 缺库必须按本机实际情况准备，禁止仅凭浏览器下载成功宣称兼容。当前机器的实际处理和限制见验收证据。

验收工具必须为每次运行生成独立数据目录、应用账号、随机密码、JWT 密钥和随机回环端口。它不加载 `.env.local`，移除继承的 Spring 外部配置/数据源、MySQL 客户端及 JVM 注入参数，将客户端登录文件指向本次目录的不存在路径，再生成本次数据库/JWT/监听配置，使用独立 JAR 快照；Flyway 初始化后只在该实例应用验收夹具。结束后停止本次进程，数据库、日志和会话信息只保留在忽略目录 `.local/acceptance/`；失败跟踪位于 `frontend/test-results/acceptance/`，禁止提交这些文件。

## 3. 手工演示

必须在隔离实例操作。终端 A 从项目根目录运行并保持前台：

```bash
./scripts/test.sh acceptance --serve
```

终端 B 从项目根目录读取本次前端地址。命令只输出访问地址，不输出密码或令牌：

```bash
python3 -c 'import json; print(json.load(open(".local/acceptance/session.json"))["env"]["ACCEPTANCE_BASE_URL"])'
```

用不同浏览器或不同浏览器个人资料分别登录，必须确保三个端的登录存储相互独立。夹具账号 `admin`、`teacher1`、`acceptance_student` 的密码均为演示密码 `123456`，仅适用于本工具的新测试库。

1. 管理员进入“课程目录”，新增代码 `CHECK-01` 的课程，填写有效院系、学分与学时；保存后刷新必须仍在。修改课程名和学分后刷新必须保留新值。删除后列表必须消失，数据库应逻辑删除并留三次审计；不能删除有教学班引用的“验收互动课程”。
2. 教师选择“独立验收学期”，打开“验收互动班”的选课名单并保持页面可见。学生选择同一学期，在课程选择页搜索 `ACCEPT-A`，点击选课并确认。教师端应自动出现“验收学生”和新增提示。学生再退课，教师端应自动移除并显示退课提示。教师教学班列表的人数也必须自动同步。
3. 学生重新选入“验收互动班”，然后打开“我的成绩”；另一个学生会话可打开“我的学分统计”。教师进入该班成绩录入，填写平时 80、期中 90、期末 100，暂存后刷新应保留，总评必须为 91。草稿不应出现在学生端。教师正式发布后，学生端应自动出现该课、3.33 绩点、3 学分及更新提示；教师不能继续改分。
4. 管理员解锁成绩后，学生端应自动撤下，获得学分应回到 0；已选学分仍为 3。当前管理员界面没有解锁按钮，这一步可用浏览器开发者工具对现有解锁调用复验，或直接运行 `grade-security.spec.ts` 的自动化用例；不得伪称该管理端页面入口已经交付。
5. 教师更正后重新正式发布，再新开学生课表；已发布成绩的课程必须仍在、不可退课。以 390、768、1440 像素分别检查三端菜单、课程弹窗和表格；宽表应在容器内滚动，不能把整个页面撑宽。

步骤 4 的现有管理员调用：Vite 代理路径为 `POST /api/grades/class/9101/unlock`，JSON 为 `{"reason":"验收更正后重新审核成绩"}`，必须携带当前管理员令牌；浏览器工具仅供本机复验，禁止将令牌复制进报告或 Git。调用路径是项目已存在的兼容入口，不能当作 `05` 中所有标准端点均已实现的证据。

## 4. 数据库与复验

验收必须核对下列数据，而非只观察“保存成功”的提示：

可在终端 B 的项目根目录读取本次客户端配置路径并进入 MySQL；禁止输出配置内容：

```bash
source scripts/env.sh
acceptance_client="$(python3 -c 'import json; print(json.load(open(".local/acceptance/session.json"))["env"]["ACCEPTANCE_MYSQL_CONFIG"])')"
MYSQL_TEST_LOGIN_FILE="$acceptance_client.disabled-login" mysql --defaults-file="$acceptance_client" --table
```

```sql
SELECT course_code, name, credit, credit_hours, deleted
FROM course WHERE course_code='CHECK-01';

SELECT tc.id, tc.enrolled_count, COUNT(e.id) AS actual_count
FROM teaching_class tc LEFT JOIN enrollment e
  ON e.teaching_class_id=tc.id AND e.status IN ('ENROLLED','COMPLETED') AND e.deleted=0
WHERE tc.id=9101 GROUP BY tc.id;

SELECT e.student_id, e.status, g.regular_score, g.midterm_score, g.final_score,
       g.total_score, g.grade_point, g.status AS grade_status
FROM enrollment e LEFT JOIN grade g ON g.enrollment_id=e.id AND g.deleted=0
WHERE e.teaching_class_id=9101;

SELECT action, target_type, target_id, result
FROM sys_audit_log ORDER BY id DESC LIMIT 20;
```

数据库命令只能使用本次忽略目录下的 `client.cnf`，不得改成开发库或外部库。测试中的失败注入触发器只允许在新隔离实例创建，并必须在 `finally` 中移除。套件末尾的 `zz-consistency.spec.ts` 必须直接检查人数不一致、超出容量、已发布但未完成、已完成但无发布成绩、故障触发器残留，五项异常数均须为 0。第二轮应从新实例重跑，成功计数、拒绝结果、回滚与跨端可见性必须一致。

## 5. 尚未覆盖的设计范围

本次核心验收不等于全部原始设计验收。院系/专业/学期/教学班完整管理写入口、教学班状态流转、批量成绩导入、完整审计切面、全部标准 API 前缀/别名及生产运维仍需后续实施。管理员成绩解锁当前为接口能力，未新增管理页面入口。浏览器引擎与视口测试不等于真实 Android/iOS 设备、Windows/macOS 或生产部署测试。禁止用本次通过结果覆盖这些边界。
