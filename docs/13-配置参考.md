# 13 配置参考

## 1. 配置来源与优先级

`scripts/dev.sh setup` 应首次生成权限为 `600` 的 `.env.local`。字段样例为根目录 `.env.local.example`，不得包含真实密钥。脚本启动时以 `.env.local` 的值覆盖同名 shell 环境变量，并导出给后端；Spring Boot 再以环境变量覆盖 `application.yml` / `application-dev.yml` 中的默认值。直接使用 Maven 启动时应自行导出这些变量，脚本不参与配置加载。

`CSMS_DB_*`、`CSMS_JWT_SECRET`、`SERVER_ADDRESS` 等变更必须重启后端；MySQL 监听端口等变更必须重启托管实例。真实数据库账号密码必须同时在数据库中修改，不能只修改配置文件。更换 JWT 密钥会使此前签发的 Token 无效。

## 2. 字段清单

| 字段 | 用途 | 必填 | 脚本默认值 / 示例 | 变更后 |
|---|---|---|---|---|
| `CSMS_DB_HOST` | 后端数据库主机 | 是 | `127.0.0.1`；托管模式禁止其他主机 | 重启后端 |
| `CSMS_DB_PORT` | 数据库 TCP 端口 | 是 | `3307`；直接启动后端的 YAML 默认是 `3306` | 重启数据库与后端 |
| `CSMS_DB_NAME` | 数据库名 | 是 | `csms` | 先准备目标库，再重启后端 |
| `CSMS_DB_USERNAME` | 应用数据库账号 | 是 | `csms`；托管模式禁止用 root 作为应用账号 | 先配置数据库账号，再重启后端 |
| `CSMS_DB_PASSWORD` | 应用数据库密码 | 是 | setup 随机生成；示例 `replace_with_random_local_password` | 同步数据库账号并重启后端 |
| `CSMS_MYSQL_ROOT_PASSWORD` | 托管实例初次设置本地 root 密码 | 托管模式必填 | setup 单独随机生成；不传给前端 | 必须同步数据库 root 账号 |
| `CSMS_MANAGE_DB` | 是否由脚本管理独立原生实例 | 否 | `1`；`0` 表示连接自行维护的数据库 | 重启项目；外部库禁止运行 live 测试 |
| `CSMS_JWT_SECRET` | JWT 签名密钥 | 本地脚本必填 | setup 生成 96 个十六进制字符；真实值禁止提交 | 重启后端，重新登录 |
| `SERVER_ADDRESS` | 后端监听地址 | 否 | `127.0.0.1` | 重启后端 |
| `SERVER_PORT` | 直接运行 JAR 时的后端端口 | 否 | 后端 YAML 默认 `8081`；验收工具随机分配 | 重启后端并同步前端代理；`dev.sh` 的检查固定使用 `8081`，不得通过此项改变脚本端口 |
| `CSMS_CORS_ALLOWED_ORIGINS` | 允许的浏览器来源，逗号分隔 | 否 | `http://localhost:5173,http://127.0.0.1:5173`；禁止通配符 | 重启后端 |
| `VITE_API_TARGET` | Vite 开发代理的后端目标 | 否 | `http://localhost:8081`；只影响开发代理，不含数据库凭据 | 重启 Vite |
| `PLAYWRIGHT_CHANNEL` | 使用已安装的品牌浏览器 | 否 | 未设置：Playwright Chromium；Windows 示例 `msedge` | 下次测试生效 |
| `CSMS_DOWNLOAD_CACHE` | 引导器下载缓存目录 | 否 | `.local/tools/downloads`；不包含账号密码 | 下次引导器运行生效 |

托管库名与用户名应仅使用字母、数字和下划线。`CSMS_DB_USERNAME` 必须是独立应用账号；数据库初次初始化只创建该库的权限。配置样例与脚本生成逻辑必须保持一致。

## 3. 初始化与敏感信息

系统表应由原生 MySQL 的初始化命令创建；业务表与演示数据必须由既有 Flyway V1～V4 迁移创建，禁止手工修改已发布的迁移脚本。已有数据目录不得自动覆盖。已有外部实例的数据不会自动导入独立开发实例（AS-16）。

必须通过环境变量向后端注入密码与 JWT 密钥，前端不得接收数据库密码。真实 `.env*` 文件、`.local/`、工具归档、日志、私钥、数据库备份和浏览器认证目录必须被 Git 忽略；`.env.example` / `.env.*.example` 仅可包含占位值。Windows 旧启动脚本的 `CSMS_MYSQL_HOME` / `CSMS_MYSQL_DATA` 必须由本地环境变量提供，实际目录禁止写入仓库。

提交前必须暂存预期改动并运行 `python3 scripts/check-privacy.py`。检查必须拒绝被强制加入 Git 的忽略文件、已知令牌/私钥、本机路径和与本地 `.env*` 相同的真实凭据，失败输出不得包含敏感值。该检查只检查当前暂存快照和已知模式，不能替代人工检查配置示例、脱敏文档及 Git 历史；修改 `.gitignore` 也不会从既有历史中移除文件。

配置分离思路参考 [12-Factor 配置](https://www.12factor.net/zh_cn/config)，本仓库的实际优先级以上述脚本行为为准。

## 4. 隔离验收配置

`scripts/acceptance.py` 不读取 `.env.local`，必须移除继承的 Spring 外部配置、数据源、MySQL 客户端及 JVM 注入参数，再生成本次数据库/JWT/监听配置，使用全新实例、随机端口和凭据；SQL 客户端必须隔离机器登录文件。测试进程使用工具注入的 `ACCEPTANCE_BASE_URL`、`ACCEPTANCE_BACKEND_URL`、`ACCEPTANCE_MYSQL_CONFIG`，使用者不应手工指向既有实例。它们是单次测试配置，没有固定默认值；新建会话后重新注入。

直接启动时，`CSMS_CORS_ALLOWED_ORIGINS` 与 `SERVER_PORT` 遵循 Spring 属性优先级，环境变量覆盖代码/YAML 默认值。`VITE_API_TARGET` 从 Vite 进程环境读取，未设置则使用代码默认值；必须通过 shell 或启动脚本导出，仅放入 Vite 的 dotenv 文件不会改变当前代理读取逻辑。测试工具为每次会话显式指定代理目标和允许来源，避免借用固定端口服务。

## 5. 原生演示服务器配置

经明确授权的演示服务器使用 [原生模板](../deploy/native/) 和 [部署指南](17-原生服务器部署与HTTPS.md)。systemd 从 root 所有、权限为 600 的 `/etc/csms/backend.env` 注入真实参数，禁止读取或上传使用者本地 `.env.local`。该环境文件覆盖单元中的同名 `Environment`；Spring 环境变量再覆盖外部 YAML 的默认值，Java 命令行属性仍遵循 Spring 自身的更高优先级。修改后必须重启后端，变更单元内容还须先 `daemon-reload`。

| 字段 | 用途 / 是否必填 | 样例或默认值 | 生效方式 |
|---|---|---|---|
| `SPRING_PROFILES_ACTIVE` | 选择独立演示配置，单元必填 | `demo`；由单元声明 | 重启后端 |
| `SPRING_CONFIG_ADDITIONAL_LOCATION` | 载入无密钥的外部配置，单元必填 | `file:/etc/csms/application-demo.yml` | 重启后端 |
| `JAVA_OPTS` | JVM 内存与故障退出参数，单元使用时必填 | `-Xms128m -Xmx512m -XX:+ExitOnOutOfMemoryError`；须按实际资源调整 | 重启后端 |
| `CSMS_DB_HOST` | 新数据库地址，可选 | 默认 `127.0.0.1`，仅允许使用本项目实例 | 重启后端 |
| `CSMS_DB_PORT` | 新数据库端口，可选 | 默认 `3307`；须与独立实例一致 | 同步实例配置并重启后端 |
| `CSMS_DB_NAME` | 新数据库名，可选 | 默认 `csms_demo` | 先准备新库及授权，再重启后端 |
| `CSMS_DB_USERNAME` | 独立应用账号，必填 | 样例 `csms_demo`，无默认值 | 同步数据库账号并重启后端 |
| `CSMS_DB_PASSWORD` | 独立应用密码，必填 | 无默认值，在目标独立生成 | 同步数据库账号并重启后端 |
| `CSMS_JWT_SECRET` | 演示服务器签名密钥，必填 | 至少 48 个随机字节生成的十六进制值，禁止沿用本地值 | 重启后端，旧令牌失效 |
| `CSMS_CORS_ALLOWED_ORIGINS` | 浏览器允许来源，本部署必填 | `https://your_server_ip`，必须替换为实际 HTTPS 来源 | 重启后端 |
| `SERVER_ADDRESS` | 后端监听地址，可选 | 默认 `127.0.0.1`，禁止新增公网监听 | 重启后端 |
| `SERVER_PORT` | 后端端口，可选 | 默认 `8081`；须与 Nginx 反代目标一致 | 同步代理配置并重启后端 |
| `TZ` | 进程时区，可选 | 样例 `Asia/Shanghai`；未设置时继承目标系统时区 | 重启后端 |

前端使用同源 `/api`，无需把目标数据库或 JWT 参数编入静态产物。TLS 配置由独立 Nginx 站点读取 `/etc/csms/tls`，证书变更必须验证后重载 Nginx；真实 IP、SSH 信息、访问密码、CA 私钥和数据库管理配置不得进入仓库。

## 6. 认证动态参数

V5 在既有 `sys_config` 中新增以下非敏感参数，通过管理员配置页或 B-22 修改；数据库值优先，无需重启。不得通过 SQL 绕过校验。已有锁定截止时间及已签发令牌的到期时间不被追溯修改。

| 参数 | 用途 / 范围 | 默认 / 示例 | 生效时机 |
|---|---|---|---|
| `auth.max_fail_count` | 连续失败锁定阈值，整数1～20 | 默认5，示例5 | 后续登录失败 |
| `auth.lock_minutes` | 锁定分钟数，整数1～1440 | 默认15，示例15 | 后续新锁定 |
| `auth.jwt_expire_seconds` | JWT有效秒数，整数60～86400 | 默认7200，示例3600 | 后续成功登录；响应 expiresIn 与实际令牌相符 |

参数缺失或被外部非法修改时，失败阈值/锁定时长回退到5/15，令牌有效期回退到 Spring `csms.jwt.expiration`（默认7200000毫秒）。后者通过外部 YAML 或命令行覆盖时需重启；正常运行应使用已迁移的数据库参数。
