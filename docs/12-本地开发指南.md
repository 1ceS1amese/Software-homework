# 12 本地开发指南

## 1. 支持环境与依赖

本轮必须以 Arch WSL、Linux x86_64、glibc 2.42 或更高作为已验证环境。Windows 的历史启动方式可以保留，但不代表本轮在 Windows 复测。其他 Linux 发行版应自行准备相同语言版本与 MySQL 8.0，不应运行 Arch 专用引导器。

| 工具 | 要求与锁定方式 |
|---|---|
| JDK | Java 17；引导器锁定 Temurin 17.0.20.1+1 |
| Maven | 3.9.12；Maven Wrapper 的下载地址在 `backend/.mvn/wrapper/maven-wrapper.properties` |
| Node.js | 22.12+；引导器锁定 22.23.3 LTS |
| pnpm | 10.16.1；`frontend/package.json` 的 `packageManager` |
| 前端依赖 | 必须按 `frontend/pnpm-lock.yaml` 安装，不应自动升级锁文件 |
| MySQL | 原生 MySQL 8.0；引导器锁定 8.0.46，客户端兼容库仅安装到 `.local/tools` |
| 浏览器 | Playwright 随锁文件版本安装的 Chromium；需要运行库和可用字体 |
| 基础命令 | Bash、Git、Python 3.12+、GNU tar（支持 zstd）、binutils 的 `ar`、OpenSSL、curl、util-linux 的 `setsid`、fontconfig 的 `fc-cache` |

依赖坐标以 registry 实际解析为准。引导器用 `scripts/linux-tools.json` 的实际下载地址与 SHA-256 固定二进制来源；禁止将工具归档、数据库文件或凭据提交到 Git。

## 2. 从干净环境获取与安装

系统依赖不足的 Arch 环境，应先运行完整系统更新与依赖安装，而非单独刷新包索引后只升级部分系统库：

```bash
# 任意目录；由使用者按自己的系统维护计划执行
sudo pacman -Syu --needed git python tar zstd binutils openssl curl util-linux fontconfig
```

以下命令均使用原生工具，禁止启动 Docker 测试。

```bash
# 希望保存项目的父目录
git clone https://github.com/1ceS1amese/Software-homework.git "UML Software"
cd "UML Software"

# 项目根目录：下载工具并验证 SHA-256，不改系统级 Java/Node 配置
python3 scripts/bootstrap-linux.py

# 项目根目录：生成 .env.local、初始化独立 MySQL 数据目录、装依赖、测试并打包后端
./scripts/dev.sh setup

# 项目根目录：启动原生 MySQL、后端和前端
./scripts/dev.sh start
```

首次下载需要网络，工具安装后应通过 `source scripts/env.sh` 选择工程内工具。迁移自 Windows 的项目若出现原生模块不匹配，应在 `frontend/` 运行 `pnpm install --frozen-lockfile --force`，然后重新 `setup`。禁止通过删除锁文件解决平台差异。

如使用已有 MySQL，必须先在 `.env.local` 设置 `CSMS_MANAGE_DB=0` 和连接信息。该模式不应初始化、停止或修改外部实例；真实链路测试入口会拒绝外部实例。

## 4. 日常运行与数据位置

以下命令必须在项目根目录执行：

```bash
./scripts/dev.sh status
./scripts/dev.sh logs
./scripts/dev.sh stop
./scripts/dev.sh start
```

后端源码改变后必须重新 `./scripts/dev.sh setup` 打包，再运行 `./scripts/dev.sh restart`。前端开发服务器自动更新源码。必须保留 `.local/mysql/data`；停止服务只应发送终止信号，不应删除数据。PID 位于 `.local/run`，前后端和数据库日志位于 `.local/logs`。本地服务只监听回环地址，未配置开机自启。

## 5. 开发与生产运行的区别

`dev.sh` 与 Vite 开发服务器只应用于本地开发。生产运行必须使用 `pnpm build` 输出的静态文件、后端可执行 JAR、独立生产配置、TLS 和正式数据库，并完成 `docs/08` 与 `docs/10` 的门禁。当前没有生产部署授权，本轮禁止执行远程部署。

## 6. 排错

| 现象 | 检查与处理 |
|---|---|
| 5173 / 8081 / 3307 被占用 | 运行 `ss -ltnp` 确认占用者；本项目可运行 `dev.sh stop`。禁止直接停止不属于本工程的进程 |
| 缺少 `.env.local` | 在根目录运行 `dev.sh setup`；禁止把示例占位密码当成已初始化数据库的密码 |
| MySQL 未就绪 | 查看 `.local/logs/mysql-init.log` 与 `mysql.log`；确认库目录可写、端口空闲、`source scripts/env.sh` 后 `mysql --version` 可执行 |
| 数据库认证失败 | 对照 `docs/13`；已有数据目录的账号密码不会随 `.env.local` 自动改动，不得删除数据来绕过认证 |
| Node / Java 指向 Windows | 运行 `source scripts/env.sh`，再检查 `command -v node`、`java -version`；需要时重跑引导器 |
| 原生模块版本不匹配 | 在 `frontend/` 使用锁文件强制重装依赖；应使用 Node 22.12+ |
| 找不到 Chromium / 浏览器动态库 | 按 `docs/14` 安装浏览器；Arch 使用工程引导器提供运行库，Ubuntu CI 使用 Playwright 的系统依赖安装 |
| Chromium 字体初始化崩溃 | 运行 `fc-list`；引导器必须安装并刷新 Noto Sans SC 字体缓存 |
| 依赖下载超时 | 检查当前环境的 HTTPS 代理与网络；禁止把代理密码提交到仓库，也不应关闭 TLS 校验来绕过错误 |

文档组织参考 [FastAPI 开发指南](https://github.com/fastapi/full-stack-fastapi-template/blob/master/development.md)；实际命令必须以本仓库脚本为准。
