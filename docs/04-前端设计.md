## 1. 选型口径说明（重要，先读）

用户指定"Vue 3 + Nuxt UI"。这里存在一个必须显式澄清的歧义：

| 方案 | 含义 | 本设计取值 |
|---|---|---|
| **方案 A（首选）** | **Nuxt UI**（Nuxt 团队组件库）+ **Vite + Vue 3 SPA** | ✅ 采用 |
| 方案 B | **Nuxt 3**（SSR 框架）+ Nuxt UI | 备选，见下 |
| 方案 C | 纯 Vue 3 组件库（Element Plus / Naive UI） | 兜底 |

- **方案 A 成立的前提**：Nuxt UI 提供了面向"非 Nuxt 的 Vue 3 应用"的安装路径（Vite 插件 + Tailwind CSS）。
- **风险**：本轮**无法联网核实**该接入方式（web_search 无 API key，见 `docs/11` AS-03）。若实施阶段证伪，按以下回退顺序处理：
  1. **方案 B**：整包切到 Nuxt 3 + Nuxt UI。本设计所有页面/组件/状态设计**可原样迁移**（`<script setup>`、Pinia、路由守卫语义一致），主要增量是 SSR 相关的 `useFetch`/`useAsyncData` 改造。影响：工期 +2~3 天，需处理 Token 读取位置（只能用 Cookie 而非 localStorage）与 SSR 中间件。
  2. **方案 C**：替换组件库，页面结构、路由、状态、权限设计全部保留，只换模板标签。影响：工期 +1 天，改动集中在"组件映射表"。
- **不变的部分**（三个方案下都成立）：目录结构、路由表、页面职责、Pinia store、权限模型、API 层、表单与错误处理规范。

> **本设计给出组件映射表（§6.4）**，实施阶段若组件库变化，只需改映射表，无需重设计页面。

## 2. 前端职责与工程约定

| 项 | 约定 |
|---|---|
| 语言 | TypeScript（`strict: true`） |
| 组件写法 | SFC + `<script setup lang="ts">` |
| 状态 | Pinia（Setup Store 写法） |
| 路由 | Vue Router 4，`createWebHistory` |
| 样式 | Tailwind CSS + 主题变量；**禁止**在组件里写全局选择器 |
| 请求 | Axios 实例 + 拦截器 |
| 类型来源 | `src/api/types.ts`，与 `docs/05` 字段逐字对应 |
| 单位 | 尺寸用 Tailwind 工具类；颜色必须用语义 token（`primary/success/warning/error/neutral`），**禁止写死十六进制** |
| 可访问性 | 所有 `icon-only` 按钮必须有 `aria-label`；表单控件必须有关联 `label` |
| 国际化 | 本期仅简体中文（AS-06） |

### 4.1 路由守卫流程

```
进入路由
 ├─ 无 Token ──────────────→ /login?redirect=<原路径>
 ├─ 访问 /login 且已登录 ──→ 按角色重定向到首页
 ├─ meta.roles 不含当前角色 → /403
 ├─ 目标页声明 requiresTerm 且 termStore 无可用学期
 │     └─ 提示"当前没有开放学期"→ 跳本角色首页
 └─ 通过 → 渲染
```

## 5. 页面详细设计

### 5.1 学生：课程选择 `/student/courses`（**核心页**）

| 区 | 内容 |
|---|---|
| 筛选栏 | 关键词（课程代码/名称）、院系、专业、教师、上课时间（周几）、"只看有余量"、"只看我的专业"、重置 |
| 列表 | 表格：课程代码/名称、学分、教师、班号、上课时间地点、已选/容量、剩余、操作 |
| 剩余列 | `<30%` 绿 / `30%~90%` 橙 / `0` 红"已满" |
| 冲突标记 | 与我已选课程冲突的行 → 整行浅红底 + 冲突说明 tooltip |
| 状态列 | 已选课程显示 `已选` 徽标；已退课显示 `可重选` |
| 操作 | `选课`（可用）/ `已选`（禁用）/ `已满`（禁用）/ `冲突`（禁用，提示原因） |
| 空态 | "当前学期没有开放的课程" + 提交按钮 |

**交互细则**
1. 页面加载与筛选变更走 `GET /teaching-classes`，**分页服务端**。
2. 展开某行可查看完整时间段与课程简介（抽屉）。
3. 点击"选课"→ 确认弹窗（含学分与冲突提示）→ `POST /enrollments`：
   - 成功 → 成功提示 + **局部刷新该行的已选/剩余** + 顶栏学分统计更新；
   - `50102` → 行内提示"名额已满" + 刷新该行；
   - `50103` → 弹窗列出冲突课程与节次；
   - `50104` → 弹窗提示缺哪门先修课；
   - `50105/50106` → 顶部警告条；
   - `50112` → 提示"人数众多，请重试"，保留按钮可再次点击。
4. 提交中按钮 loading 且禁用，防止重复提交（服务端仍有唯一键兜底）。
5. **选课预检**：批量进入页面时对当前页前 10 条调 `POST /enrollments/check`（P1），用于提前灰显；预检失败不阻断列表渲染。

### 5.3 学生：我的成绩 `/student/grades`

- 按学期分组卡片展开：表头 `课程 | 教师 | 学分 | 平时 | 期中 | 期末 | 总评 | 绩点 | 是否及格`。
- 顶部汇总：本学期已获学分、加权平均、GPA。
- 只显示 `status=PUBLISHED` 的成绩；未发布的不出现（不得泄露草稿）。
- 不提供任何编辑入口。

### 5.4 教师：我的教学班 `/teacher/classes`

| 列 | 内容 |
|---|---|
| 课程 / 班号 | |
| 学期 | |
| 选课人数 | `31/40`，进度条展示满员度 |
| 成绩状态 | 未开始/录入中/已发布 徽标 |
| 上课时间 | 折叠展示多条时间段 |
| 操作 | 查看名单、录入成绩、查看统计 |

### 5.5 教师：成绩录入 `/teacher/classes/:id/grades`

| 区 | 内容 |
|---|---|
| 状态条 | 教学班信息 + 成绩状态徽标 + `暂存` / `发布成绩` 按钮 |
| 权重提示 | "平时 30% / 期中 30% / 期末 40%"，来自 `GET /configs` |
| 录入表 | 每行一名学生：`学号 | 姓名 | 平时 | 期中 | 期末 | 总评(自动只读) | 及格` |
| 操作 | 编辑输入框 → 前端实时算总评预览 → 点"暂存"提交 `POST /grades` |
| 发布 | 点"发布成绩" → 弹窗列出**空缺名单** → 确认 → `POST /grades/publish` |
| 发布后 | 输入框全部只读 + 顶部"已发布"提示 + 显示"如需修改请联系管理员" |
| 导入（P2） | "导入成绩"按钮 → 上传 CSV → 预览差异表格（新增/更新/错误行）→ 确认导入 |

- **前端算总评仅作预览**，以服务端返回为准；保存成功后用服务端 `totalScore` 覆盖本地值。
- 离开页面前若存在未保存修改，弹出"未保存的修改将丢失"确认。

### 5.6 管理员：概览看板 `/admin/dashboard`

- 4 个指标卡：教学班数、选课总数、总体满员率、待处理（未发布成绩班数）。
- 图表：近 6 学期选课趋势折线、满员度分布饼图、Top10 热门课程条形图。
- 所有数据来自 `GET /stats/*`，**禁止本地假数据**（FR-STAT-05、`10` AC-16）。
- 图表组件统一封装 `StatChart`，处理空数据（显示空态而非空白画布）。

### 5.7 管理员：用户管理 `/admin/users`

- 筛选：角色、院系、专业、状态、关键词；分页表格。
- 操作：新建（弹窗表单）、编辑、重置密码（二次确认 + 展示一次性密码并提示复制）、启停用（危险操作需确认）、分配角色、删除（有业务数据时按钮禁用并 tooltip 说明原因）。
- 敏感信息：手机号/邮箱默认脱敏显示，鼠标悬停显示"需查看完整信息"的提示。

### 5.8 管理员：课程管理 `/admin/courses`

- 表格 + 新建/编辑弹窗（含先修课程多选）。
- 先修关系编辑：选择先修课程时**排除自身及其下游**，避免成环（B-19 会再次校验 30501）。

### 5.9 管理员：统计报表 `/admin/stats`

- 4 个 Tab：选课总览 / 按课程 / 满员度分析 / 成绩分布。
- 表格支持导出 CSV（前端生成，UTF-8 BOM 以兼容 Excel 中文）。
- 空数据统一显示"暂无数据"，不显示 0 值图表。

### 5.10 管理员：审计日志 `/admin/audit-logs`

- 筛选：操作人、模块、动作、结果、时间范围。
- 表格列：时间、操作人、角色、模块、动作、目标、结果、IP。
- 点击行 → 抽屉展示 before/after JSON 差异对比（前后值并排，变化字段高亮）。

### 5.11 公共：修改密码 `/profile/password`

| 区 | 内容 |
|---|---|
| 表单 | 旧密码、新密码、确认新密码 |
| 校验 | 新密码长度 ≥ 8 字符，含字母+数字；确认密码一致性；旧密码必填 |
| 提交 | `PUT /auth/password` → 成功提示"密码已修改" + 清除 Token + 跳转登录页 |
| 强制改密 | `mustChangePwd=true` 时由路由守卫强制跳转本页，隐藏"旧密码"字段（管理员重置场景），提交后跳转对应角色首页 |

## 7. 状态管理（Pinia）

| Store | 状态 | 关键动作 | 说明 |
|---|---|---|---|
| `auth` | `token`、`user`、`permissions`、`loaded` | `login`、`logout`、`fetchMe`、`hasPerm(code)` | Token 持久化到 `localStorage`；启动时若存在 Token 则 `fetchMe()` 校验有效性 |
| `term` | `terms`、`currentTermId`、`loading` | `fetchTerms`、`switchTerm`、`isEnrollingNow` | 全局学期上下文；`isEnrollingNow` 供前端灰显"未到选课期" |
| `dict` | `depts`、`majors`、`courseTypes` | `fetchDepts`、`fetchMajors` | 字典缓存，登录后拉一次；提供"刷新"动作 |
| `enroll` | `myEnrollments`、`summary`、`conflictIds` | `fetchMine`、`add`、`remove`、`recomputeConflicts` | 供课表与课程列表共享的本地缓存；选退课成功后局部更新，**不整页刷新** |
| `ui` | `sidebarCollapsed`、`colorMode`、`globalLoadingCount` | `startLoading`/`stopLoading` | 全局 UI 状态 |

**规则**
- Store 中**不保存从服务端可随时重取的派生数据**，例如列表查询结果留在页面内（`useTableQuery` composable 管理）。
- 任何跨页面共享的"业务数据"才进 Store。
- Store action 失败必须向上抛出或置 `error`，由调用方决定提示，**不在 Store 里弹 toast**。

### 7.1 Composables

| Composable | 职责 |
|---|---|
| `useTableQuery(fetcher, defaultParams)` | 分页/排序/筛选状态与自动重查，统一 loading/empty/error |
| `useDebounceFn` | 关键词输入防抖（300ms） |
| `useFormatters` | 学分/分数/时间/枚举中文格式化 |
| `useConfirm` | Promise 化的确认弹窗 |
| `useDownloadCsv` | 前端导出 CSV（含 BOM） |

## 8. API 层与请求拦截

### 8.1 `api/request.ts` 要点

| 环节 | 行为 |
|---|---|
| 请求拦截 | 注入 `Authorization`；`GET` 追加 `traceId` 便于对日志 |
| 响应拦截 | 解包信封：`code===0` → 返回 `data`；非 0 → 交给统一错误处理 |
| 401 处理 | 清 Token → 跳登录并带 `redirect`；**并发 401 只跳一次**（用标志位） |
| 403 处理 | 提示无权限并跳 `/403`（仅对整页跳转；局部操作仅 toast） |
| 404 处理 | 由调用方决定是否显示空态 |
| 5xx 处理 | 提示"系统繁忙"并展示 `traceId`（仅开发环境） |
| 超时 | 10s；超时提示"请求超时，请检查网络" |

### 8.2 分模块 API 文件

`api/` 下按 `docs/05` §3 分节拆分为 `auth.ts`、`users.ts`、`base.ts`（depts/majors/terms/courses/configs）、`teachingClasses.ts`、`enrollments.ts`、`grades.ts`、`stats.ts`、`audit.ts`。每个文件**方法名与端点编号对应**（如 `enrollments.ts#create` → E-01），便于对照实现。

### 8.3 类型定义

`api/types.ts` 至少包含：`ApiResponse<T>`、`PageResult<T>`、`PageQuery`、`User`、`TeachingClass`、`ClassSchedule`、`Enrollment`、`Grade`、`Term`、`Course`、`ErrorCode`（`05` §4 的联合字面量类型）。

**约定**：后端枚举（`02` §7）在前端以 `as const` 对象 + 派生联合类型镜像，`const` 断言保证拼写错误在编译期暴露（`10` AC-12）。

## 9. 权限设计

三层防护，前端两层是**体验优化**，服务端才是安全边界：

| 层 | 手段 |
|---|---|
| 路由级 | `meta.roles` + 全局守卫，越权 → `/403` |
| 页面级 | `v-perm="'grade:publish'"` 指令控制按钮渲染 |
| 数据级 | 前端按 `auth.hasPerm()` 控制 Tab/列的可见性 |

| 权限码 | 含义 |
|---|---|
| `user:read` `user:write` `user:reset-pwd` | 用户管理 |
| `base:dept:write` `base:major:write` `base:term:write` `base:course:write` `base:config:write` | 基础数据 |
| `class:write` `class:publish` `class:delete` | 教学班 |
| `enroll:self` | 选退课 |
| `grade:read` `grade:write` `grade:publish` `grade:unlock` | 成绩 |
| `stat:school` `audit:read` | 统计与审计 |

**明确禁止**：前端不得仅靠"隐藏按钮"作为权限控制。`10` AC-09 的验收方式是**绕过前端直接调接口**。

## 10. 表单与校验规范

| 项 | 规范 |
|---|---|
| 校验时机 | 失焦校验 + 提交前全量校验 |
| 错误展示 | 字段下方红字，不用 toast |
| 提交中 | 按钮 loading + 禁用 + 表单只读，防重复提交 |
| 后端错误回填 | `10000` 的字段级错误映射到对应表单项 |
| 必填标识 | 星号 + `aria-required` |
| 长表单 | 分步或分组展示，避免单页超过 15 个字段 |
| 危险操作 | 二次确认；不可逆操作（删除、取消教学班）需输入对象名称确认 |

## 11. UI/UX 规范

| 主题 | 规范 |
|---|---|
| 主题色 | 使用 UI 库语义 token；支持亮/暗色（`UColorMode`），暗色下图表需同步换色 |
| 表格 | 行高 44px；操作列固定右侧；表头吸顶；超过 10 列时横向滚动 |
| 分页 | 默认 20 条，可选 10/20/50/100 |
| 加载 | 首次加载用骨架屏；刷新用局部 loading 遮罩；按钮 loading 单独表现 |
| 空态 | 必须有图标 + 一句说明 + 一个下一步动作 |
| 错误 | 页面级错误（加载失败）显示重试按钮；操作级错误用 toast |
| 危险色 | 删除/取消用 `error` 色 + 确认弹窗 |
| 响应式 | 基准 1440px；≥1280 三栏；768~1280 两栏（侧边栏收起）；<768 仅保证"可查询可查看"，复杂表格提示"建议使用更大屏幕" |
| 无障碍 | 键盘可达（Tab/Enter/Esc），弹窗 Esc 可关，焦点锁定在弹窗内 |

## 12. 提示文案规范

| 场景 | 规范 |
|---|---|
| 文案来源 | **一律取后端 `message`**，前端不二次加工业务文案 |
| 错误码兜底 | 未知 `code` → "操作失败，请稍后重试（编号 {code}）" |
| 成功提示 | 1 秒内自动关闭；批量操作结果改为结果对话框，不逐条 toast |
| 危险结果 | 选课失败要说明**原因与下一步**（如"与《高数》冲突，是否查看我的课表？"） |
