# 14 测试与检查指南

## 1. 测试边界与数据

本轮测试必须使用原生工具，禁止启动 Docker、Docker Compose 或 Testcontainers。普通单元测试和模拟接口浏览器测试不需要数据库；真实链路测试只允许本工程管理的回环地址开发实例，禁止连接生产库或任意外部数据库。

`frontend/tests/live` 保留登录和只读查询，登录会更新本地登录元数据。课程写入、20 人抢 1 席、成绩保存/发布/解锁、审计故障回滚与跨端互动位于 `frontend/tests/acceptance`，必须由 `scripts/acceptance.py` 新建独立原生实例运行，不允许复用 `.env.local` 或开发库。详细步骤与边界见 [三端验收](16-三端联动与数据库验收.md)。

## 2. 首次准备浏览器

```bash
# 项目根目录
source scripts/env.sh
cd frontend
pnpm exec playwright install chromium
```

Arch 的运行库与中文字体由引导器准备。Ubuntu CI 可以运行 `pnpm exec playwright install --with-deps chromium`。测试默认使用 Playwright 自带 Chromium；`PLAYWRIGHT_CHANNEL=msedge` 只适用于已安装 Edge 的环境。

## 3. 测试入口

以下统一入口必须从项目根目录执行：

| 命令 | 内容 | 外部依赖 |
|---|---|---|
| `./scripts/test.sh` | 后端 JUnit、前端 Vitest、模拟接口 E2E | Chromium；无需 MySQL |
| `./scripts/test.sh backend` | 后端规则与异常映射测试 | JDK 17；无需数据库 |
| `./scripts/test.sh unit` | 前端状态与失败分支测试 | Node / pnpm |
| `./scripts/test.sh e2e` | 三角色页面、权限、失败提示、响应式布局 | Chromium；5173 端口 |
| `./scripts/test.sh live` | 真实后端、MySQL 的三角色链路 | 先运行 `dev.sh start`；本地 8081、3307 |
| `./scripts/test.sh acceptance` | 全新原生 MySQL 的增改删、并发、事务、跨端与兼容性 | MySQL 8 / Java 17 / Python；三浏览器及运行库；随机回环端口 |
| `python3 -m unittest discover -s tests` | 验收工具正常退出及取消时清理子进程 | Python 3 / Linux；无需数据库或浏览器 |
| `./scripts/check.sh` | Git 空白格式、Shell 语法、TypeScript、前端构建 | 不需要数据库或浏览器 |

普通浏览器测试会自动启动前端，也会复用已经运行的 5173 服务；不要同时启动另一个占用同端口的服务。浏览器用例使用独立上下文和接口桩；失败截图、错误上下文应落到 `frontend/test-results/`，禁止提交。

## 4. 单个测试与手工命令

```bash
# 项目根目录：单个后端测试类
./scripts/test.sh backend -Dtest=EnrollmentRuleCheckerTest

# 项目根目录：按标题筛选前端测试
./scripts/test.sh unit -t '学期'
./scripts/test.sh e2e -g '学生不能进入管理员页面'
./scripts/test.sh live -g '管理员'

# 全新隔离库，只验证课程写入；不用先启动开发库
./scripts/test.sh acceptance -- course-admin.spec.ts --project=chromium
# 保留隔离实例，另一个终端可用 --current 重跑指定功能
./scripts/test.sh acceptance --serve
# 另一终端，项目根目录
./scripts/test.sh acceptance --current -- grade-security.spec.ts --project=chromium

# 前端目录：类型检查与生产构建
cd frontend
pnpm typecheck
pnpm build

# 后端目录：测试、编译与打包（测试默认执行）
cd ../backend
bash ./mvnw -B -ntp test
bash ./mvnw -B -ntp clean package
```

检查入口先运行 `python3 scripts/check-privacy.py` 检查 Git 暂存快照。提交前必须先暂存预期改动，确保检测的是实际待上传内容；隐私检查无需数据库、浏览器或网络，不得输出敏感值。机器记录应保存到 Git 忽略的 `.local/private-notes/` 或 `*.local.md`。

格式入口只检查 Git 变更中的行尾空白、末尾空行与缩进空白，同时检查 Shell 语法；它不等同于全仓库 Prettier 或 ESLint。暂未引入这些工具，不应声称已执行未配置的检查。

## 5. CI 与证据

`.github/ci.example.yml` 提供提交隐私检查、后端 JUnit、前端单元测试、类型检查、构建及模拟接口 E2E 的 CI 配置样例，尚未启用。CI 不应配置数据库容器、调用付费模型或部署网站；真实本地数据库链路由使用者手动运行。

具备工作流写入权限后，应在项目根目录执行以下命令并提交；推送后必须以 Actions 实际回执确认结果：

```bash
mkdir -p .github/workflows
cp .github/ci.example.yml .github/workflows/ci.yml
```

验证记录应保存到 `docs/evidence/`；详细运行日志保存在本机 `.local/logs/`。失败时必须先修复原因，再重跑受影响的检查。测试通过只能证明当前已覆盖的路径。

统一脚本入口参考 [HTTPX 贡献指南](https://www.python-httpx.org/contributing/)，浏览器隔离与稳定定位参考 [Playwright 实践](https://playwright.dev/docs/best-practices)。
