## 1. 测试策略

### 1.1 分层

| 层 | 范围 | 工具 | 目标占比 | 是否需数据库 |
|---|---|---|---|---|
| 单元测试 | `domain` 规则、计算器、状态机、工具类 | JUnit 5 + Mockito + AssertJ | 70% | 否（内存） |
| 集成测试 | Mapper SQL、事务边界、并发 | Spring Boot Test + **Testcontainers MySQL** | 20% | 是（真实 MySQL 容器） |
| 接口测试 | 端点契约、鉴权、错误码、序列化 | MockMvc | 8% | 是 |
| E2E | 三角色主流程 | Playwright（前端起真实 dev/preview + 后端） | 2% | 是 |

**关键原则**：**并发正确性必须用真实 MySQL 验证**。H2 与 MySQL 的锁与 SQL 语义存在差异，用 H2 测并发等于没测（`docs/11` RISK-07）。

### 1.2 测试金字塔配比理由

| 关注点 | 主要落在哪层 |
|---|---|
| BR-04/05/06 三重校验 | 单元测试（`EnrollmentRuleChecker` 是纯函数式设计，`03` §3.1） |
| BR-03 不超卖 | **集成测试 + 并发专项**，不可只用单测 |
| BR-12/13 成绩发布 | 集成测试（需真实事务与 `FOR UPDATE`） |
| BR-14 数据隔离 | 接口测试 + E2E |
| UI 交互与文案 | E2E |

## 4. 集成测试用例（后端，含数据库）

### 4.1 选课主流程（TC-I-01 ~）

| 用例 | 步骤 | 期望 |
|---|---|---|
| TC-I-01 | 正常选课 | 200；`enrollment.status=ENROLLED`；`enrolled_count` +1 |
| TC-I-02 | 校验失败路径（时间冲突） | 409 + `50103`；**`enrolled_count` 未变化**；无 `enrollment` 行 |
| TC-I-03 | 名额已满 | 409 + `50102`；计数不变 |
| TC-I-04 | 事务回滚验证：在校验通过后人为抛错 | 计数与记录**均未变更**（BR-07） |
| TC-I-05 | 退课 | `WITHDRAWN`；计数 -1；行仍存在（BR-10） |
| TC-I-06 | 重复退课 | 幂等成功，计数**不再 -1** |
| TC-I-07 | 退课后重选 | 同一行被更新回 `ENROLLED`（不新增行，不触发唯一键冲突） |
| TC-I-08 | 退课后名额被他人占用 | 别人选课成功，容量校验有效 |
| TC-I-09 | 学期不在选课窗口 | `50105`，无副作用 |
| TC-I-10 | 教学班非 `PUBLISHED` | `50106`，无副作用 |
| TC-I-11 | 管理员代选课 | 200；`enrollment.source=ADMIN`；`enrolled_count` +1；审计记录操作人为管理员 |

### 4.2 并发专项（**最高优先级用例组，TC-I-20 ~**）

| 用例 | 场景 | 期望 |
|---|---|---|
| TC-I-20 | 50 个线程同时选同一个只剩 1 个名额的班 | 恰好 1 成功，49 失败；`enrolled_count == capacity` |
| TC-I-21 | 20 个线程同时选同一班（容量 40，已选 0） | 恰好 20 成功，20 失败；无重复行 |
| TC-I-22 | 50 个线程对**同一学生**选同一班 | 恰好 1 条记录（唯一键兜底） |
| TC-I-23 | 100 并发混合：3 个班同时抢 | 总成功数 == 总容量 |
| TC-I-24 | 并发选 + 并发退混合 5 秒 | 结束后 `enrolled_count` 与真实计数一致（对账 SQL 返回 0 行） |
| TC-I-25 | 死锁压力（多班多时段交叉） | 无 500；重试后成功或返回 `50112` |
| TC-I-26 | 压测后一致性对账 | `02` §6.7 的对账查询**返回 0 行**（`10` AC-07） |

**执行要求**：
- 用 `ExecutorService` + `CountDownLatch` 确保真正同时发起；
- 每个线程独立事务与独立连接；
- 断言同时检查：HTTP 返回码、`enrollment` 行数、`teaching_class.enrolled_count` **三者一致**。

### 4.3 成绩（TC-I-30 ~）

| 用例 | 步骤 | 期望 |
|---|---|---|
| TC-I-30 | 批量保存 50 条成绩 | 全部落库，`total_score` 由服务端计算 |
| TC-I-31 | 一条分数越界 | `60101`；**整批 0 条写入**（不部分成功） |
| TC-I-32 | 发布（无空缺） | 成绩 → `PUBLISHED`；`enrollment` → `COMPLETED`（BR-13 同一事务） |
| TC-I-33 | 发布（有空缺） | `60102`；无任何变更 |
| TC-I-34 | 发布后修改 | `60103` |
| TC-I-35 | 管理员解锁 | 回到 `DRAFT`；`unlock_count+1`；审计含 reason |
| TC-I-36 | 重复发布 | 幂等成功，不产生第二次 `COMPLETED` 副作用 |
| TC-I-37 | 发布事务中途失败 | 成绩与选课状态**同时回滚**（验证同事务） |
