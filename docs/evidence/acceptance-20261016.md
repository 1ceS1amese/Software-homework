# 三端与数据库验收记录（2026-10-16）

本记录只保留可复用步骤与脱敏结论。测试必须使用 `scripts/acceptance.py` 创建的全新原生 MySQL 实例、后端 JAR 快照和前端；禁止连接开发库、生产库，禁止启动 Docker。上游 00 / 02 / 05 契约保持不变。

## AC-01 管理员课程增改删

- 初查：课程页只有查询和只读说明，未提供完整写链路，不符合前端增改删验收要求。
- 修复：新增课程表单与编辑、删除确认；后端校验字段、院系/专业归属、重复代码和关联引用，逻辑删除并在同一事务写审计。可显式配置 Vite 代理目标和 CORS 允许来源，默认本地入口继续可用。
- 首轮：Chromium 实际浏览器 2 项通过，覆盖页面增改删与拒绝路径，直接查询数据库验证持久化。
- 二次校验：重新创建隔离实例，再运行 `course-admin.spec.ts --project=chromium`，2 项通过（10.4 秒）；增加审计顺序、中文校验提示、拒绝后原始值未变断言。
- 验收现象：新增后写入名称/学分/学时；修改后刷新仍为新值；删除后列表消失、数据库 `deleted=1`；对应审计顺序为 CREATE_COURSE、UPDATE_COURSE、DELETE_COURSE。引用课程未被删除，学生不能写入。

## 待修复问题的基线

在隔离实例中，教师读取其他教师的班级名单、伪造其他班选课记录保存成绩，两项测试均预期 HTTP 403，实际 HTTP 200。后续修复必须用相同拒绝断言复验，不能只检查页面入口隐藏。

## AC-02 选课权限与事务

- 修复：个人选退课入口限制学生角色；教师名单校验教学班归属；事务内复核目标为有效学生，同一学生写入串行；保留原子容量 UPDATE 与重复唯一键兜底。退课按教学班→选课记录顺序锁定。管理员代选写 ADMIN 来源，选退课审计与业务同事务。
- 首轮：Chromium `enrollment.spec.ts` 4 项通过（8.7 秒）。二次校验再次运行 4 项通过（7.1 秒），增加管理员审计断言。
- 可观察结果：跨教师名单读取返回 403；教师不能选课；重复选课返回 50101；重复退课不重复扣名额；重选复用同一关系；停用账号旧令牌不能退课；20 个不同学生并发抢 1 席，1 次成功、19 次 50102，数据库容量计数与有效选课关系均为 1。

## AC-03 学生选退课 → 教师端互动

- 基线：学生在真实页面选课后，另一教师会话名单仍为空，测试失败；原页面只在进入时加载。
- 修复：教师名单与教学班人数每 5 秒同步，恢复前台时立即补查；新增/退课显示页面状态提示及通知。筛选条件保留，背景刷新保留原数据；路由/学期切换丢弃旧响应，离开页面停止定时器。
- 首轮：学生真实页面选课、退课，教师独立会话无需刷新即可收到名单与提示，1 项通过（13.6 秒）。
- 二次校验：扩展名单筛选保留和教师列表人数同步，2 项通过（26.2 秒）；数据库分别为 ENROLLED/计数 1、WITHDRAWN/计数 0。两端使用独立浏览器上下文与各自令牌，不使用模拟接口。
- 边界：这是在线页面的状态同步和提示，不承诺关闭浏览器后的离线通知或逐条历史消息；按 AS-18 处理。

其余功能点的结果须在实际测试后逐项补齐；本记录不代表全套原始设计功能已经交付。
