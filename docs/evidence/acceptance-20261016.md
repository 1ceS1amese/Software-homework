## AC-03 学生选退课 → 教师端互动

- 基线：学生在真实页面选课后，另一教师会话名单仍为空，测试失败；原页面只在进入时加载。
- 修复：教师名单与教学班人数每 5 秒同步，恢复前台时立即补查；新增/退课显示页面状态提示及通知。筛选条件保留，背景刷新保留原数据；路由/学期切换丢弃旧响应，离开页面停止定时器。
- 首轮：学生真实页面选课、退课，教师独立会话无需刷新即可收到名单与提示，1 项通过（13.6 秒）。
- 二次校验：扩展名单筛选保留和教师列表人数同步，2 项通过（26.2 秒）；数据库分别为 ENROLLED/计数 1、WITHDRAWN/计数 0。两端使用独立浏览器上下文与各自令牌，不使用模拟接口。
- 边界：这是在线页面的状态同步和提示，不承诺关闭浏览器后的离线通知或逐条历史消息；按 AS-18 处理。

## AC-04 成绩保存、发布与解锁

- 修复：保存前校验每条选课关系属于当前班级、有效状态、唯一正整数 ID 与 0～100 分/最多两位小数；整批失败不写入。总评与绩点按服务端权重计算，忽略伪造总评。保存/发布/解锁锁定同一教学班，成绩发布和选课完成同事务，并写审计；解锁原因校验 5～300 字。
- 首轮：Chromium 3 项通过（13.7 秒），原越权基线由 HTTP 200 改为 403；覆盖混合合法/非法批次、页面暂存修改、发布锁、学生草稿不可见、管理员解锁。
- 二次校验：新隔离实例 4 项通过（14.6 秒），扩展 0/100 分边界、0/4.00 绩点和过长原因；在仅供验收的数据库中用临时触发器令发布末尾审计失败，HTTP 500 后成绩仍 DRAFT、选课仍 ENROLLED，移除故障后重试成功为 PUBLISHED/COMPLETED。
- 测试设施：隔离 MySQL 关闭二进制日志，使验收账号能创建/移除本实例的临时故障触发器；未给应用全局管理权限，未改变开发或生产配置。首次故障测试因隔离实例触发器权限被拒，调整测试实例后重新验证通过。

## AC-05 教师发布 → 学生端互动与一致性

- 基线：两项失败。教师发布后，另一个已打开的学生成绩页仍无成绩；已完成课程从课表和已选学分查询中消失。
- 修复：学生成绩与学业概览自动同步；发布/撤回显示变化提示，保留关键词与结果筛选并防止旧学期响应覆盖。个人课表、学分统计、选课学分上限及时间冲突将有效的已完成课程纳入；课表详情禁止退选已完成课程。
- 首轮：Chromium 2 项通过（26.2 秒）。二次校验 2 项通过（23.3 秒），扩展已完成课程继续占用学分上限的断言。
- 结果：教师页面录入 80/90/100，服务端总评 91、绩点 3.33，学生独立会话自动展示并收到提示，概览获得 3 学分；管理员解锁后成绩与获得学分自动撤下。课表及已选学分仍保留 3 学分，发布后退课返回 60103；临时设上限 4 时再选 2 学分课返回 50109，测试后还原配置。

## AC-06.2 响应与审计追踪

- 后续兼容断言发现正常响应的 traceId 为 null，未登录响应没有完整信封；旧审计写入也未包含来源地址与追踪号。
- 修复：请求追踪先于鉴权执行；成功、业务拒绝及系统错误复用当前追踪号；鉴权拒绝返回中文统一信封；审计补齐 IP 与追踪号。外部追踪号只接收 8～32 位安全字符，超长值重新生成。
- 单点复验：三个浏览器各运行课程审计 2 项、响应/CORS 1 项，共 9 项通过（31.9 秒）；验证响应体与头一致、中文未登录拒绝、恶意长追踪号、正确/错误来源，以及课程三次审计均有 IP/追踪号。后端原有 6 项测试通过。

## AC-06.3 本地图标

- 基线：WebKit 在三个视口捕获到外部图标服务跨域异常。启用扫描后首次复验仍失败，原因是默认扫描未包含路由 TypeScript，导航图标继续发出外部请求。
- 修复：Nuxt UI 从已锁定的本地图标包打包页面与路由中使用的图标；扫描明确覆盖 `src` 的 Vue / TypeScript，修正无效教师导航图标名，不新增运行时外部依赖。
- 单点复验：保留页面无异常断言，增加外部图标请求数必须为 0 的断言；Chromium / Firefox / WebKit 各 390、768、1440 像素共 9 项通过（1.6 分钟），包含真实课程表单写入/删除、三角色导航、课表与旧调用；生产构建通过。

## 运行方式与兼容性边界

- 真实链路套件位于 `frontend/tests/acceptance`，不模拟业务请求。每轮由 `scripts/acceptance.py` 新建独立原生 MySQL、应用账号、随机凭据与回环端口，运行 Flyway 和验收夹具；使用后端独立 JAR 快照，结束后只停止本轮进程。开发库、真实 `.env.local` 和 Docker 均未使用。
- 完整套件为每个浏览器项目 20 项，共 60 项；包含不同宽度的页面交互、独立角色会话、真实 API 拒绝、并发与数据库断言。末尾检查五类数据库异常数，而非只累计页面“成功”提示。
- 测试浏览器来自锁定的 Playwright 1.63.0：Chromium 153.0.8010.12、Firefox 155.0、WebKit 26.6。三种视口为 390 / 768 / 1440 像素。
- 本次非官方支持的 Linux 运行环境没有使用系统包安装器。缺失运行库仅在忽略目录/浏览器缓存中准备；逐项检查动态库并实际启动三个引擎。由于 Playwright 的系统库预检不能识别此专用库目录，本轮进程设置 `PLAYWRIGHT_SKIP_VALIDATE_HOST_REQUIREMENTS=1`，跳过的是主机库预检，浏览器、页面错误、数据库及业务断言均实际执行。专用库路径与机器配置不进入 Git；其他机器应按 docs/16 的官方受支持系统流程准备。
- 引擎/视口通过不能代替真实 Android/iOS 设备、Safari 品牌浏览器、Windows/macOS、网络断连恢复、性能压测或生产部署验收；五秒同步也不是离线消息中心。

## AC-06.4 验收客户端配置隔离

- 收尾复查发现 MySQL 的 `--no-defaults` / `--defaults-file` 仍可能读取机器登录文件。用单独构造的测试登录文件指向回环端口 1，基线客户端查询失败；未读取真实登录文件或连接外部数据库。
- 修复仅涉及验收工具和 SQL 测试助手：移除继承的 MySQL 客户端变量，将登录文件明确指向本次目录的不存在路径；初始化 SQL 固定为本实例 socket、root 空口令并使用隔离环境。此机制依据 [MySQL 8.0 环境变量说明](https://dev.mysql.com/doc/refman/8.0/en/environment-variables.html)，不改变用户的 HOME 或登录文件。
- 业务源码/JAR 在两轮完整验收后保持不变；本项单独继承伪造登录文件、错误客户端密码/端口，在两个额外全新实例各运行课程 CRUD/拒绝/数据库一致性 3 项，分别通过（10.5 秒、10.6 秒）。初始化、测试助手和真实业务写入都正确连接新实例，五项异常均为 0；两次服务均已停止。该项加固的是测试工具，未再修改业务实现。
