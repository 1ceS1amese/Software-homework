## HTTPS 与访问边界

- 私有自签名根 CA 签发含实际 IP SAN 的服务器证书。严格 `curl --cacert` 核对公开入口、深层路由和健康接口均为 HTTP 200；TLS 1.2 与 TLS 1.3 分别协商成功。证书生成器还实际验证了错误 IP 拒绝、密钥权限及重复执行不更换密钥。
- 浏览器默认不信任私有 CA，访问者须核对管理员交付的 CA 指纹并建立信任。此限制没有通过购买证书、改用域名或跳过实际 CA/IP 核验来掩盖。
- 本次公网 HTTP 请求收到上游 Apache 的外部跳转，而目标本机以相同 Host 请求返回预期的 HTTPS 301。因此**公网 HTTP 自动跳转未验收通过**，本项目的可用入口按完整 `https://<server-ip>/` 交付；上游网络入口由服务器所有者按接入条件处理，不能归咎于已正确的本机 Nginx 配置。
- 浏览器套件因私有 CA 使用单独的 `ignoreHTTPSErrors` 上下文；CA 链/IP/有效期以独立严格请求验证。本机仍为非官方支持的 Linux 测试环境，专用运行库路径下跳过 Playwright 主机库预检，三个引擎、全部页面/权限/数据库断言均实际执行。不能将此结果表述为 Safari 品牌、真实移动设备或所有操作系统验收。
